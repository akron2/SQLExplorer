# Статус реализации SQLExplorer

Дата: 2026-09-12. Версия приложения: 0.1.6. Статус: базовые рабочие сценарии и каталог объектов с контекстным автодополнением реализованы и проверены на Windows x64.

## Выполнено

SQLExplorer остаётся Electron/React/TypeScript-приложением с Monaco и react-data-grid, но демонстрационная модель соединений заменена рабочей.

Архитектурные границы:

- renderer изолирован (`sandbox`, `contextIsolation`, без Node integration) и использует предметный preload API;
- пароли, локальные пути, драйверы и процессы не раскрываются renderer сверх необходимых публичных DTO;
- профили хранятся в SQLite пользователя, пароли шифруются асинхронным Electron `safeStorage`;
- при недоступном safeStorage пароль остаётся только в памяти текущего запуска и не записывается открытым текстом;
- PostgreSQL, Oracle Thin и каждая уникальная конфигурация Oracle Thick работают в отдельных Electron UtilityProcess;
- Oracle Thick runtime key включает Oracle Client `libDir` и Oracle Net `configDir`, поэтому разные клиенты/каталоги могут работать одновременно;
- физическая сессия и транзакция закреплены за SQL-вкладкой;
- runtime state не сохраняется между запусками, тексты и файловое состояние документов сохраняются;
- прикладных периодических ping/`SELECT 1` нет;
- SQL после connection-level error не повторяется автоматически.

### Профили и Oracle

- Профили Oracle и PostgreSQL создаются, проверяются, изменяются и удаляются из интерфейса.
- Отдельно отображаются сохранённые реквизиты и фактическое состояние сессии.
- Для Oracle доступны Thin/Thick, host/port/service, TNS alias и произвольный connect string.
- Поддержан парольный SYSDBA в Thin и Thick; привилегия постоянно обозначается в проводнике, вкладке, toolbar и status bar.
- Глобальный каталог Oracle Net настраивается в Oracle settings; профиль может задать override.
- Список алиасов читается из `tnsnames.ora`; приложение файл не редактирует.
- Список установок Oracle Client хранит пользовательские названия и `libDir`; путь к `oci.dll` при импорте нормализуется до каталога.
- Изменение connection-critical параметров повышает `profileVersion`; существующая сессия становится `outdated`.

### Сессии и переподключение

- Состояния: `disconnected`, `connecting`, `connected`, `lost`, `outdated`, `error`.
- Execution state и transaction state хранятся отдельно.
- PostgreSQL обрабатывает `error/end`; Oracle использует локальный `isHealthy()` перед повторным использованием standalone connection.
- Периодической сетевой проверки нет; `connected` означает последнее известное состояние.
- Известно потерянная/отключённая сессия создаётся следующим явным Execute.
- Ошибка во время драйверного execute инвалидирует сессию, но не вызывает скрытый retry.
- Зависшее закрытие курсора ограничено по времени и переводит сессию в `lost` вместо зависания следующего Execute.
- Connect/Reconnect/Disconnect доступны возле соединения активной вкладки.
- Disconnect/Reconnect с изменённой транзакцией требуют явного Rollback; скрытый Commit исключён.
- Commit/Rollback/Disconnect остаются доступны для уже открытой сессии даже после удаления сохранённого пароля.
- При смене Thin/Thick или runtime key старая сессия закрывается в исходном процессе до создания новой.

### Вкладки и состояние интерфейса

- Левый клик по `+` создаёт документ в текущем контексте.
- Стрелка, правый клик и `Shift+F10` открывают список профилей; browser mock имеет эквивалентное React-menu.
- Пустой SQL-документ может существовать без соединения.
- Карточка профиля показывает агрегат реальных сессий, а не наличие пароля.
- Production bootstrap не содержит демонстрационных профилей или метаданных.
- Контекстное меню SQL-вкладки содержит Save, Save As и Close.

### Каталог объектов и автодополнение

- Метаданные хранятся индексированным каталогом в пользовательской SQLite; полный снимок удалён из bootstrap и renderer, `metadata_cache` выведена из обращения.
- Словарные запросы идут отдельным служебным соединением: Oracle `ALL_OBJECTS`/`ALL_TAB_COLUMNS`/`ALL_SYNONYMS`, PostgreSQL `pg_class`/`pg_proc` с проверками привилегий.
- Подсказки учитывают текущую схему (`CURRENT_SCHEMA`/`search_path`), квалификатор `схема.` (включая `sys.`), алиасы, CTE и quoted identifiers; без квалификатора предлагаются объекты текущей схемы, для Oracle — доступные PUBLIC синонимы.
- Селектор схемы вкладки меняет контекст сессии; после каждого Execute контекст перечитывается, а каталог инвалидируется при смене схемы, `search_path`, пользователя или профиля.
- Explorer показывает схемы и постраничный список объектов с поиском; схемы крупнее 20 тыс. объектов обслуживаются запросами по требованию, колонки загружаются лениво.
- Подсказки ограничены 200 элементами с признаком неполноты; устаревшие ответы отбрасываются по версии документа.

### SQL-файлы

- Видимые Open/Save находятся возле вкладок; полное меню «Файл» содержит New/Open/Recent/Save/Save As/Save All/Close.
- Поддержаны системные dialogs, accelerators и drag-and-drop нескольких файлов.
- Документ хранит путь, кодировку, BOM, EOL и disk version.
- Disk version включает размер, mtime и SHA-256, поэтому внешнее изменение не перезаписывается молча.
- Конфликт предлагает Compare, Reload, Save As, Overwrite или Cancel.
- Кодировка определяется по BOM, строгому UTF-8 и затем эвристике; при сомнении открывается выбор с preview.
- Поддерживаются UTF-8/16/32, Windows-125x, CP866, KOI8, ISO-8859 и другие iconv-lite кодировки.
- Обычный Save сохраняет выбранные encoding/BOM/EOL.
- Перед legacy-save выполняется обратная проверка: неподдерживаемые символы не заменяются молча на `?`.
- Dirty close предлагает Save/Don't Save/Cancel; transaction resolution выполняется раньше file resolution.
- Закрытие приложения поддерживает Commit/Rollback all и Save/Discard all.
- Явно отвергнутые изменения не возвращаются из workspace autosave после перезапуска.

## Фактические проверки

| Проверка | Результат |
|---|---|
| ESLint + строгий TypeScript | проходит |
| Модульные тесты | 139 тестов в 12 файлах проходят: каталог, автодополнение, настройки интерфейса, workspace, файлы, соединения |
| Browser E2E | 8 сценариев проходят, включая каталог схем, поиск объектов, смену текущей схемы и масштаб интерфейса |
| Electron E2E | 7 сценариев проходят: живые БД, автодополнение объектов, 100 документов, profile persistence/safeStorage, Windows-1251, close guard, reconnect UI и сохранение масштаба между перезапусками |
| Каталог 200 тыс. объектов | префиксный поиск в SQLite укладывается в бюджет модульного теста (500 мс, фактически миллисекунды) |
| Автодополнение в Electron | после подключения `Ctrl+Space` показывает объекты схемы (`EMPLOYEES` на живом Oracle) |
| Быстрый перезапуск | повторный запуск на том же userData не падает с `database is locked` (`PRAGMA busy_timeout = 5000`) |
| Oracle 21c XE Thin | basic, TNS alias, custom connect string, словари, PUBLIC синонимы, `SYS`, paging, rollback, cancel проходят |
| Oracle 21c XE Thick / Client 19.32 | basic, TNS alias, custom connect string и запросы проходят |
| Oracle SYSDBA | Thin и Thick проходят с локальным test secret |
| Одновременные Oracle runtime | Thin и два разных Thick runtime key проходят в одном запуске |
| PostgreSQL 10.23 | словари, контекст и смена `search_path`, paging, rollback, cancel, session loss и reconnect проходят |
| Безопасный reconnect | первая команда на невыявленной мёртвой сессии завершается ошибкой без retry; следующая явная команда подключается заново |
| Изоляция вкладок | незакоммиченные данные одной PostgreSQL-вкладки не видны другой |
| Файлы | Windows-1251 round trip с CRLF, внешнее изменение и comparison проходят в Electron |
| Secret persistence | профиль переживает перезапуск; пароль отсутствует в публичном payload/profile JSON и открытом виде SQLite |
| Electron, 100 документов | один editor/model, восстановление окна проходит |
| Windows x64 package | ASAR package запускает renderer и полную DB-матрицу через UtilityProcess |
| `npm audit` | 0 известных уязвимостей |

Интеграционные DML используют только учебные схемы и откатываются. Тест потери соединения завершает собственную PostgreSQL-сессию тестового пользователя. Пароли не печатаются в результатах проверок.

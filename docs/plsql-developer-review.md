# Изучение установленного PL/SQL Developer 17

Дата: 2026-09-09. Статус: завершён первый практический проход основных сценариев; расширенный осмотр и нагрузочное профилирование остаются отдельными этапами.

Связанные документы: [архитектура](architecture.md), [автодополнение](autocompletion.md), [производительность](performance.md).

## Назначение

Изучение установленного приложения является частью проектирования SQLExplorer. Нужно понять реальные действия пользователя, удобные сочетания команд, организацию соединений, редакторов и результатов. Выводы должны опираться на наблюдаемые сценарии, а при отсутствии доступа к сценарию — явно обозначаться как сведения из документации.

Рабочий референс: `C:\Program Files\PLSQL Developer 17\plsqldev.exe`. Установленная версия файла сообщает 17.0.

Ошибки захвата и геометрии относятся к инструменту осмотра. Они не являются доказательством неисправности PL/SQL Developer или RDP. Текстовое чтение элементов окна работает.

## Продолжение живого осмотра: 2026-09-09

Обнаружены два монитора 1920×1080 с координатами (0, 0) и (1920, 0). Целевое окно находится на первом: его границы на момент осмотра — (30, 20), 1860×1000. Для снимков используется резервное чтение видимой области конкретного окна с учётом DPI и виртуального рабочего стола. Действия мышью и клавиатурой выполняются через Computer Use. Штатный захват по-прежнему возвращает ошибку SetIsBorderRequired.

В исходном экземпляре открыты SQL Window и Preferences. При открытии Preferences получен [снимок состояния «Не отвечает»](assets/plsql-developer/02-preferences-wait.png); позднее настройки открылись, приложение отвечало. Длительность задержки не измерялась непрерывно. Это наблюдение при инструментальном осмотре; влияние самого инструмента и причина задержки не установлены. Эпизод не равнозначен воспроизведению исходного сценария восстановления множества окон.

Управление полями Preferences оказалось ненадёжным: диалог не предоставлен как отдельное доступное окно, а щелчок отклонялся как попадание в другое окно того же процесса. Ввод OCI-пути не подтвердился. Перед закрытием диалога проверено, что Apply неактивен; затем Preferences закрыт клавишей Enter без внесённых изменений.

Для проверок с БД открыт отдельный экземпляр установленного приложения с тестовым профилем на D: (`.local/developer-review`), параметрами Registry/InstanceName `SQLExplorerReview`, InstantClient и UserID. Эти параметры документированы в главе 37.4 руководства. Пароль взят из локальных реквизитов стенда и не помещается в отчёт. Тестовый экземпляр подключился к `SQLX@127.0.0.1:1521/XEPDB1`.

Измерение задержки автодополнения не проводилось: эти проверки подтверждают содержимое и взаимодействие при явном вызове F6. Массовый ввод через инструмент не используется как доказательство поведения автоматического вызова при обычном посимвольном наборе.

При двух открытых SQL-окнах, из которых запрос был исполнен только в первом, сервер показывал 2 сессии SQLX с программой PL/SQL Developer. После первого исполнения во втором окне их стало 3. Это наблюдение согласуется с отдельной рабочей сессией на исполняемое окно; точная связь SID и окон не трассировалась.

Проверка отмены разделена на два запуска: в первом 60-секундное ожидание успело завершиться естественно во время переключений, поэтому его нельзя считать успешной отменой. Во втором отправлены Shift+Escape и команда Break, после чего получено ORA-01013. На итоговом кадре таймер показывал 1:00; немедленная отмена не подтверждена. Запросов SQLX, остающихся в PL/SQL lock timer, после проверки не было.

Для Copy выполнен Ctrl+C на выбранной ячейке, однако ожидаемое значение в текстовом чтении системного буфера не подтверждено. Попытка выбрать Copy в контекстном меню отклонена инструментом как попадание в другое окно. Это ограничение проверки, а не доказанный дефект копирования в Developer. Контекстное меню затем закрыто.

Тестовые запросы не меняли таблицы учебной схемы. Тестовый экземпляр оставлен открытым с двумя SQL-документами; длительных запросов и модальных ошибок в нём нет. [Итоговое рабочее пространство](assets/plsql-developer/20-final-workspace.png).

### Значение для SQLExplorer

- Ориентир Oracle-автодополнения должен включать конкретные колонки с типами, члены пакетов и именованные параметры; список ключевых слов не обеспечивает наблюдаемое удобство.
- В текущем режиме оригинал действительно использует самостоятельные внутренние рамки SQL-окон. Это подтверждает различие с предлагаемой моделью документов и ограниченного числа представлений, но не доказывает причину зависаний.
- Связь документа с соединением и сохранение редактора рядом с результатом полезны для нашего рабочего пространства.
- Вспомогательная статистика не должна блокировать обычное выполнение SQL модальным сообщением при недостаточных правах. Для MVP SQLExplorer сбор такой статистики не предусматривается.
- Показатели времени из строки состояния оригинала не являются сравнительным бенчмарком SQLExplorer.

## Наблюдения в запущенном приложении

Через дерево доступности подтверждены:

- Панели Connections, Objects и Window List в общей группе.
- Отдельная панель PL/SQL Clipboard.
- Элементы навигации Application, Workset, Document, Open, Save и Close.
- Поле Find и панели Templates и Files.
- Категории объектов Oracle, включая Functions, Procedures, Packages, Package bodies, Types, Triggers, Tables, Views, Materialized views, Sequences, Synonyms и Database links.

Дерево доступности не позволяет само по себе определить внешний вид, видимость всех панелей, стоимость их отрисовки или удобство размещения. Эти свойства не считаются проверенными.

| Настройки Code Assistant | Вызов, фильтрация, задержка, вставка одного/нескольких элементов, параметры | Руководство изучено; UI не проверен |
| Code Assistant с объектами БД | Алиасы, колонки, пакеты, параметры, локальные записи и курсоры | Алиас, фильтрация, пакет и именованные параметры подтверждены; записи, курсоры и сложные области видимости остаются |

Для сценариев с БД используется явно выбранное тестовое окружение. Контексты подключения и содержимое существующих баз не предполагаются известными из факта установки приложения.

Подготовлен [отдельный Oracle 21c XE](oracle-test-environment.md) с учебной схемой SQLX. Его проверка через SQL*Plus не заменяет осмотр соответствующих сценариев в PL/SQL Developer.

## Как результаты влияют на SQLExplorer

После каждого проверенного сценария фиксируются последовательность действий, наблюдаемое поведение, полезные детали взаимодействия и требования к нашему клиенту. Полученные резервным способом снимки находятся в `docs/assets/plsql-developer`.

Сейчас в архитектуре уже учтено сохранение состояния документов отдельно от представлений. Проверка референса должна уточнить интерфейс и рабочие сценарии; наличие множества узлов доступности не служит основанием утверждать, что оригинальное приложение перерисовывает их все.

Перед окончательной детализацией взаимодействия редактора, соединений, подсказок и результатов необходимо вернуться к этому плану. Непроверенные сценарии не должны превращаться в отчёт о выполненных испытаниях.

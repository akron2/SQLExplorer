# SQLExplorer: проектные документы

Дата актуализации: 2026-09-11. Статус: базовые рабочие сценарии реализованы и проверены.

SQLExplorer — кроссплатформенный настольный клиент для Oracle и PostgreSQL с современным интерфейсом. Ориентир по удобству — PL/SQL Developer. Основной проблемный сценарий: восстановление главного окна при большом числе открытых внутренних рабочих окон.

## Что зафиксировано

- Oracle и PostgreSQL входят в первую версию; вкладки с разными СУБД могут быть открыты одновременно.
- Oracle Thin и несколько конфигураций Thick работают одновременно; поддержаны TNS alias, custom connect string и парольный SYSDBA.
- Профили управляются из UI, а пароли сохраняются через Electron safeStorage.
- Состояние профиля отделено от состояния физической сессии; периодические ping и скрытый retry SQL исключены.
- SQL-файлы открываются и сохраняются через видимый UI с сохранением кодировки, BOM и EOL.
- Приложение должно быть кроссплатформенным и иметь современный компактный интерфейс.
- Скрытые документы сохраняют состояние, но не должны добавлять работу по отрисовке при восстановлении окна.
- Рабочий стек: Electron, TypeScript, React, Monaco, react-data-grid, node-oracledb, pg/pg-cursor и SQLite.
- Автодополнение подключается через заменяемые провайдеры. Первый кандидат для оценки — модули Bytebase для Oracle и PostgreSQL; окончательный движок не выбран.

## Что пока не определено

Минимальные версии серверов, полная матрица ОС/CPU, глубина поддержки PL/SQL и PL/pgSQL, PostgreSQL SSL, Oracle Wallet/TCPS/external authentication и реальная рабочая нагрузка пользователя.

Численные показатели в документах являются начальными целями для проверки. Измерений производительности нашего приложения и испытаний кандидатов автодополнения пока нет.

В PL/SQL Developer 17 проведён первый практический проход: SQL-окна, результаты, подсказки колонок/пакетов/параметров, подгрузка, переключение при выполнении и восстановление с двумя документами. Отчёт содержит 20 снимков и явно отмеченные ограничения; массовое зависание при восстановлении пока не воспроизведено.

Для проверок установлен Oracle 21c XE в Docker и Instant Client 19.32 на D:. Подключение SQL*Plus с Windows, учебная схема и сохранность данных после пересоздания контейнера проверены. Отдельный экземпляр Developer подключён к этой схеме; готовые движки автодополнения SQLExplorer ещё не испытывались.

## Реализация

Базовая реализация работает: Electron/React/TypeScript, Monaco, react-data-grid, SQLite и изолированные UtilityProcess для PostgreSQL и Oracle Thin/Thick. Текущий проверенный состав и команды находятся в [статусе реализации](implementation-status.md).

Первые инженерные проверки должны закрыть два основных риска: восстановление интерфейса с 1/20/100 документами и фактическую пригодность готового автодополнения. Выбор Electron и наличие исходников Bytebase сами по себе не подтверждают скорость или качество будущего приложения.

Для PostgreSQL пользователь разрешил использовать существующий контейнер `confluence-postgres`, относящийся к другому тестовому проекту. Проверены PostgreSQL 10.23, база `confluence`, схема `public` и чтение метаданных 126 таблиц. Новый контейнер не требуется; для проверок с изменением данных планируется отдельная учебная база в том же сервере. Подробности — в [описании стенда](postgres-test-environment.md). Проверка Oracle 19c остаётся отдельным пунктом: установленный 21c XE её не заменяет.

Со стороны пользователя наиболее полезны несколько типичных SQL/PLSQL-сценариев и приоритет редактирования/компиляции пакетов, DBMS_OUTPUT и параметров процедур. Это позволит уточнить следующий срез и подобрать представительные проверки. Версия доступного PostgreSQL определена инструментально; минимальная поддерживаемая версия продукта ещё не утверждена. Матрицу ОС/CPU, PostgreSQL SSL и исключённые пока Oracle Wallet/TCPS/external-auth сценарии необходимо определить до заявления их поддержки.

Пользователь оценивает отзывчивость в повседневной работе. Инструментальные замеры и техническую проверку движков автодополнения выполняет ассистент. Эти проверки не зависят от автоматизации окон PL/SQL Developer. Создан интерактивный макет рабочего экрана; он показывает поведение интерфейса на подготовленных данных, а не работу настоящего SQL-движка.

В локальном окружении обнаружены команды Node.js, npm, pnpm и Git; совместимость конкретных версий с будущими зависимостями ещё не проверена. Go не обнаружен в PATH и понадобится для сборки кандидата Bytebase, если будет выбран этот путь. Само отсутствие Go не мешает проектированию или работе над оболочкой.

Изменения принятых архитектурных решений следует отражать в этих документах. Команда зафиксировать проектирование не означает переход к написанию приложения.
